# 0007 — The Schema IR travels as JSON through `serde`

- Status: accepted
- Date: 2026-10-27

## Context

The engine needs to consume the model description generated by Python. The options were:
pass Python objects into the binding (which puts PyO3 in the logic path and breaks the
separation), invent a bespoke binary format, or use JSON.

## Decision

`serde` + `serde_json` in `keydex-core`, behind the `schema` feature. `Schema::from_json`
parses and validates the contract version; the binding only transports the text.

## Consequences

- Two new dependencies in the core: `serde` (with `derive`) and `serde_json`.
- The IR is decoupled from the transport: tomorrow it can come from a file, the network or
  another language without touching the logic.
- IR parsing cost is negligible next to parsing the configuration files.
- The `schema` feature allows compiling the core without schema support for
  dictionary-only use.
